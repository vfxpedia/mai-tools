### 1.1 확장과 동반 앱 사이: 네이티브 메시징으로 옮긴다

2 판은 확장이 127.0.0.1:28771 로 HTTP 를 보낸다. 다음 판은 **Chrome 네이티브 메시징** (`chrome.runtime.connectNative`) 으로 옮기기를 제안한다.

| | 지금 (HTTP 포트) | 네이티브 메시징 |
|---|---|---|
| 포트 | 연다 (다른 프로그램과 겹침, 2 판에서 실제로 겹쳤음) | 열지 않는다 |
| 누가 말할 수 있나 | 출처 고정 · 헤더 검사로 막음 | 등록된 확장 id 만 (브라우저가 막음) |
| 설치 | 서버만 띄우면 됨 | 동반 앱 설치 때 운영체제에 등록 (Windows 는 레지스트리) |
| 동반 앱이 꺼져 있을 때 | 확장이 실패를 받음 | 확장이 부르면 브라우저가 띄움 |

휴대폰 화면용 HTTP 포트 (127.0.0.1:28770, 사설망 공유로만 밖에) 는 그대로 둔다. 결정은 이 문서 검토 때 받는다 (10 절).

## 2. 확장 안의 모듈

| 모듈 | 하는 일 | 2 판에서 |
|---|---|---|
| 브라우저 어댑터 | 탭 · 창 · 묶음 · 재우기 · 방문 기록 · 북마크 API 를 한 곳에서 감쌈. 다른 브라우저는 이 모듈만 바꾼다 | `background.js` 에 흩어져 있음 |
| 모으기 | 탭 이벤트 (열림 · 바뀜 · 닫힘 · 옮겨짐 · 붙음 · 떨어짐), 묶음 이벤트, 앞에 있는 탭이 바뀌는 때 (머문 시간), 방문 이벤트 (NEBULA 일 때) | 2 초 뒤 전체 보고 |
| 주소 정리 | 비밀 파라미터 빼기, 거르는 사이트, 한 페이지는 하나 | Python `sanitize.py` 와 확장 `export.js` 에 둘 |
| 규칙 | 분류 규칙, 거르는 사이트, 비밀 이름 목록 | `rules.default.json` |
| 저장 | IndexedDB (확장 쪽 사본 또는 동반 앱이 없을 때의 정본) | `chrome.storage.local` |
| 동작 실행 | 그 순간 다시 확인 → 실행 → 결과 | `core.js` (그대로 이어 씀) |
| 화면 | 사이드 패널 (홈 · 보드 · 찾기 · 카드), 팝업 (짧은 상태) | 동반 앱이 낸 웹 페이지 |

**주소 정리와 규칙은 하나의 JSON 과 하나의 시험 표로.** 지금은 Python 과 JavaScript 에 같은 규칙이 따로 있다. 다음 판은 규칙을 JSON 하나로, 「이 주소는 이렇게 되어야 한다」 시험 표를 JSON 하나로 두고, 양쪽 시험이 같은 표를 읽는다 (규칙이 갈라지면 시험이 실패).

**만드는 방식**: 확장 코드가 커지므로 TypeScript 와 묶음 도구 (esbuild) 를 쓰고, 시험은 지금처럼 Node 로 돌린다. 결과물은 빌드 없이 실을 수 있는 파일이고, 출처 정책 (`script-src 'self'`) 을 지킨다.

## 4. 카드 상태 기계 (05 의 3 절)

상태: `열림` → (마지막 탭이 닫힘) → `일정 중 (단계 1 ~ 4)` → `별` · `블랙홀` · `대기`.

| 사건 | 결과 |
|---|---|
| 마지막 탭이 닫힘 (대상 조건을 채울 때, R-21-2) | `일정 중`, 닫힌 때 = 지금, 단계 1 (2 일) |
| 간격이 됨 | 그날 카드 대기열에 넣음 (하루 상한 안에서, 넘치면 다음 날 앞쪽) |
| 오른쪽 | `별` |
| 왼쪽 | 왼쪽 연속 + 1. 3 이면 `블랙홀`, 아니면 다음 단계 |
| 다음 간격까지 답 없음 | 「답 없음」 기록, 연속은 그대로, 다음 단계 |
| 4 단계가 끝남 | `별` 도 `블랙홀` 도 아니면 `대기` |
| 일정 중에 다시 열림 | `열림` (일정 멈춤). 다시 닫히면 처음부터 |
| 다시 열어 30 초 이상 머묾 | `별` (블랙홀에서도) |
| 블랙홀이 된 지 1 년 | 카드 한 장 |

이 표 전부가 단위 시험이 된다 (08).

## 5. 동기화와 암호화

- **변경 기록 방식**: 기기마다 자기 변경을 차례 번호와 함께 적고, 다른 기기의 기록을 받아 합친다. 같은 칸을 두 기기가 바꾸면 나중 시각을 쓰고 앞의 것을 기록에 남긴다 (03 의 6b 절)
- **암호화**: 기기에서 암호화한 사본만 동기화할 곳에 둔다. 열쇠는 사용자가 정한 암호 문구에서 만들고 기기 안에만 둔다 (브라우저의 WebCrypto, AES-GCM). 새 기기를 붙일 때는 이미 붙은 기기가 보여 주는 코드로 넘긴다. 열쇠를 잃으면 사본은 못 연다 (각 기기의 자료는 남는다)
- **어디에**: Drive 는 앱 전용 칸, 내 서버는 폴더 하나 (사설망으로 공유), 구독은 우리 중계 서버 (암호문만 받고 넘김)
- **기기 사이 명령**: 기기마다 서명 열쇠를 만들고, 명령에 서명한다. 확장은 붙은 기기의 서명만 받는다 (R-42-1). Ed25519 를 쓰되 WebCrypto 지원 판을 확인하고, 안 되면 P-256 서명

## 6. 메모리 실측 (동반 앱)

- 2 판의 `memory.py` 를 이어 쓴다: Chrome 프로세스의 전용 메모리 합 (약 0.1 초), GPU 는 `nvidia-smi` 와 Windows 의 GPU 메모리 계수기
- 재우기 · 닫기 직전과 20 초 뒤 (R-09-1). 다른 프로그램 몫이 섞인다는 표시 (R-09-3)
- 예상 절감 = 이 기기의 지난 실측에서 「재운 탭 하나당 평균」 (R-09-2). 첫 실측 전에는 숫자를 내지 않는다
- macOS · Linux 의 같은 값은 확인 필요 (운영체제별 프로세스 메모리 읽기)
- 탭 하나하나의 메모리를 프로세스와 짝짓는 것은 공개 확장 API 로는 안 된다고 알고 있다 (프로세스 API 는 개발 채널 전용, 확인 필요). 그래서 묶음 단위로만 잰다

## 7. 모델 연결부

```
classify(pages)  -> [{id, category, confidence}]
summarize(pages, body?) -> [{id, line}]
relate(pages)    -> [{a, b, kind, confidence}]
```

- 입력은 제목 · 주소. 본문은 사용자가 고른 탭만 (R-60-2)
- 출력은 정해진 JSON 모양. 모양이 틀리면 버리고 규칙으로 돌아간다
- 공급자: 규칙 (늘), PC 안 모델 (OpenAI 호환 로컬 서버), 클라우드 모델들, 사용자 자기 키. 어느 판에서 무엇을 쓰는지는 BM (비공개)
- 묶어서 부르기 · 한 달 상한 · 같은 사람 안 캐시. 사용자 사이 캐시는 없다
- 키는 운영체제 보관소 (N-13)

## 8. 에이전트 창구 (MCP)

- 동반 앱이 stdio MCP 서버로 뜬다. 포트를 열지 않는다 (R-25-3)
- 도구 셋: `search(query, limit)` · `recent(days)` · `page(id)`. 모두 읽기 전용 (R-25-1)
- 결과의 모든 글 칸은 「웹사이트가 정한 글」 표시 안에 넣고, 도구 설명에 「자료이지 지시가 아니다」를 적는다 (R-25-2)
- 켤 때 「결과가 에이전트의 모델 공급자에게 간다」를 알리고 동의를 받는다 (R-25-4)
- 거르는 사이트 · 블랙홀 · 지운 것은 결과에 나오지 않는다 (블랙홀은 사용자가 묻을 때만)

## 9. 2 판에서 옮기는 길

1. 동반 앱이 `~/.mai/tabs/library.json` 을 읽어 새 저장 (SQLite) 으로 옮긴다. 옮기기 전에 사본을 남긴다 (N-31)
2. 확장은 새 판이 처음 뜰 때 옛 `chrome.storage.local` 의 기기 id 를 이어 쓴다
3. 2 판의 화면 (127.0.0.1:28770) 은 한 판 동안 함께 두고, 사이드 패널이 같은 일을 하면 내린다
4. 2 판의 시험 (85 개, 실제 Chrome 11 가지) 은 모두 다음 판에서도 통과해야 한다
