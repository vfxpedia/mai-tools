# mai-resume

[English](README.md)

AI 코딩 세션의 사용 한도가 차기 직전에 세션들에 마무리를 알리고, 한도가 풀리면 다시 깨워 이어 가게 한다.

한도에 걸린 세션은 일하던 중에 멈추고, 세션 안의 예약 알림도 한도 중에는 돌지 않아 아무도 깨우지 못한다. mai-resume 는 세션 밖에서 돌아서 세션들이 멈춰도 살아 있다.

## 하는 일

1 분 (`poll_s`) 마다:

1. [Orca](https://www.onorca.dev) 의 살아 있는 에이전트 창을 센다 (`orca terminal list`). 새 세션은 손으로 목록에 넣지 않아도 잡힌다. Claude 창과 Codex 창은 Orca 의 에이전트 표식으로 가르고, 엔진마다 자기 한도를 따른다
2. 한도 파일 (`~/.mai/limits.json`, mai-gauge 상태 표시줄이 쓴다) 과 창마다의 화면을 읽는다
3. 한 엔진의 한도 구간이 **새로 잰 값으로** `warn_pct` (5 시간 93 %, 주간 98 %) 를 넘으면 그 엔진의 세션마다 그 구간에 **한 번 멈춤**을 보낸다: 안전한 지점까지만 마무리 · HANDOFF 적기 · 멈추기 · GPU 작업은 건드리지 않기. 같은 구간에 나중에 생긴 세션도 받는다. `notice_pct` (주간 85 %) 부터 멈춤 전까지는 대신 **알림**을 한 번 보낸다: 하던 일은 계속 (팀장 10/20). 한도 파일이 `limits_stale_s` 보다 낡았으면 **누구도 멈추게 하지 않고**, `stale_warn_pct` 이상일 때 「낡은 값」 표시를 단 알림만 보낸다. 이미 멈춤을 보낸 구간에는 뒤에 알림을 보내지 않는다. (10/20: 주간 85 % 에서 멈추게 하면 codex 가 14 % 를 남긴 채 닷새를 논다)
4. 화면에 `You've hit your ... limit · resets <시각>` 이 뜬 창은 이미 멈춘 것이므로, 한도 파일에 안 나타났어도 그 시각에 **재개를 예약**한다
5. 풀림 시각 + `resume_grace_s` 뒤에, 경고했거나 멈춘 세션마다 **한 번 재개**를 보낸다: HANDOFF 를 다시 읽고 이어 가기
6. **맥락 캐시를 잇는다**: `keepalive_s` (55 분, 캐시 수명 1 시간 안) 동안 쉰 Claude 세션에 짧은 신호를 한 번 보낸다. 쉰다는 것은 화면 끝에 Claude Code 가 턴을 마치고 남기는 `done 오전/오후 hh:mm` 줄이 있고 진행 표시가 없다는 뜻이다. 일하는 세션은 스스로 캐시를 이으므로 시계만 다시 걸고, 경고 · 재개 문구를 보낸 것도 신호로 센다. 한도 구간이 걸린 동안 (경고 뒤 재개 전) 과 화면에 한도 걸림 문구가 뜬 창에는 보내지 않는다. 그때는 요청이 막혀 캐시도 못 잇고 한도만 쓴다. 처음 본 창은 시계만 건다. 입력창에 글이 있어 기다리던 신호는, 보낼 수 있게 된 때 그 창이 일하는 중이거나 그 사이 새 턴을 마쳤으면 버린다. 신호가 맞는 것은 정한 그 순간의 쉼뿐이다 (10/26: 27 분 기다린 신호가 일하던 세션에 들어가 「멈춤」 으로 읽힘). 문구는 「하던 일이 있으면 그대로 계속, 없으면 idle」

## 보내는 규칙

- 글이 들어 있는 입력창에는 아무것도 치지 않는다. Orca 의 화면 읽기는 Claude 입력창에 쳤지만 아직 안 보낸 글을 보여 주지 않는데, 그 동안 입력 줄 끝의 빈칸이 1 에서 0 으로 바뀐다 (10/20 실측). 이것을 읽고, 보내기 바로 직전에 한 번 더 본다. `defer_give_up_s` 넘게 못 보낸 문구는 버리고 기록한다
- 일하는 중인 창에는 대기열의 다음 지시로 들어간다 (Claude 가 지금 일을 끝낸 뒤 처리, 실제 창 시험으로 확인)
- 같은 문구 (창 · 종류 · 구간) 는 두 번 보내지 않는다. 문구는 한 줄이고, Orca 실행 파일을 인자 목록으로 직접 부른다. 셸을 거치지 않는다 (cmd 를 거치면 여러 줄 문구가 첫 줄에서 잘렸다)
- 한 기기에 하나만 돈다 (localhost 포트 잠금). 매 회차 맥박을 남기고, 비정상으로 멈췄다가 다시 뜨면 `notify_cmd` 로 알린다

## 설치

Python 3.9 이상, 다른 패키지 없음.

```
pip install -e tools/mai-resume
mai-resume run --once --dry-run      # 한 회차만, 보낼 것을 기록만 하고 보내지 않음
mai-resume status                    # 맥박 확인, 낡았으면 종료값 1
```

로그온 때 창 없이 자동 시작:

- **Windows**: `powershell -ExecutionPolicy Bypass -File tools/mai-resume/autostart/register-windows.ps1 -Pythonw <pythonw.exe>` 가 예약 작업 `mai-resume` 를 등록한다 (로그온 시작 + 안 돌고 있으면 다시 띄우는 5 분 반복)
- **Linux**: `tools/mai-resume/autostart/mai-resume.service` (systemd 사용자 단위, 설치 순서는 파일 머리에)
- **macOS**: LaunchAgent 로 `mai-resume run` (아직 묶지 않음)

설정 · 파일 · 시험 · 한계는 [README.md](README.md) 의 표와 같다.

## 뒷받침 지킴이 (`fallback/limit_guard.py`, 10/26)

이 지킴이의 첫 시제품을 Claude 세션용 대기 지킴이로 남긴 것이다. 같은 세 가지 (한도 전 멈춤 · 풀린 뒤 재개 · 캐시 유지) 를 보내지만 **mai-resume 가 돌지 않을 때만** 보낸다. 판마다 mai-resume 의 잠금 포트 `127.0.0.1:28766` 을 bind 해 보고, 이미 쓰는 중이면 아무것도 보내지 않고 경고 기록도 남기지 않는다 (로그에 `STANDBY` 한 줄). 비었으면 `ACTIVE` 를 남기고 맡는다. 한 창은 한 도구만: 같은 Claude 세션을 여기에는 대기로만 적는다.

붙어 보는 (connect) 방식이 아니라 bind 로 본다. mai-resume 는 대기열 하나로 listen 하고 연결을 받지 않아서, 붙어 보기를 거듭하면 대기열이 차고 그 뒤로는 살아 있어도 시간 초과가 난다 (10/26 실측, `tests/test_fallback.py` 가 재현).

설치 · 실행은 [README.md](README.md) 의 같은 절. 설정 예시 `fallback/config.example.json` (주간 98 %, `primary_lock_port` 0 이면 검사 안 함). Orca 실행 파일은 `ORCA_CLI_COMMAND`, 없으면 Windows 는 `%LOCALAPPDATA%\Programs\orca` 의 `orca.exe`, 그 밖은 `orca-ide` (Linux 의 맨 `orca` 는 GNOME 화면 낭독기).

## 보낼 창 목록 (10/20)

`~/.mai/resume/targets.txt` 에 창 이름표를 한 줄에 하나씩 적는다 (`2580fc05` 처럼 앞부분만 적어도 되고 `#` 뒤는 메모). 판마다 다시 읽으므로 고친 뒤 재시작이 필요 없다. 파일이 있으면 적힌 창만 신호를 받고, 비어 있으면 아무 창도 받지 않는다. 파일이 없으면 모든 창을 보고 로그에 그렇게 적는다. 팀장이 더는 쓰지 않는 옛 세션이 재개 · 캐시 유지 신호를 받고 끝난 일을 다시 진행한 일 뒤에 생겼다. 재개 문구는 「멈춘 일만 이어 가고 끝났으면 대기」, 캐시 유지 문구는 「대기 한 단어 · 일을 시작하지 말 것」 이다.

## 다른 세션에 한 줄 보내기 (10/20)

세션끼리 보고를 보낼 때는 `orca terminal send` 를 바로 쓰지 말고 `python -m mai_resume send --to <창> --text <글>` 을 쓴다. 입력 줄이 비어 있고 5 초 간격 두 번 화면이 같을 때만, 보내기 직전에 한 번 더 보고 보낸다. 10 분 (`--wait`) 안에 조용해지지 않으면 보내지 않고 종료값 4. 10/20 에 팀장이 lead 창에 치는 중에 super2 의 보고가 붙어 들어간 일 뒤에 생겼다.

## Codex 계기판 자동으로 붙이기 (10/20)

보낼 창 목록에 있는 Codex 창 옆에 계기판 창이 없으면, 지킴이가 그 창을 나눠 `mai-codex-gauge watch --session <ID>` 를 띄운다. ID 는 계기판이 쓰는 `~/.mai/sessions/*.json` 의 창 이름표로 찾는다. 같은 탭에 이미 계기판이 보이면 (제목에 Mods, 또는 미리보기에 계기판 줄) 열지 않는다. 창 하나에 한 번만 열고, 팀장이 닫으면 다시 열지 않는다 (그 창이 새로 뜨면 다시). 계기판이 깔려 있지 않으면 (`~/.codex/mai-codex-gauge/src/cli.mjs` 없음) 아무것도 안 한다. 끄려면 config.json 에 `"companion": false`.
