### 1.1 확장과 동반 앱 사이: 네이티브 메시징으로 옮긴다

2 판은 확장이 127.0.0.1:28771 로 HTTP 를 보낸다. 다음 판은 **Chrome 네이티브 메시징** (`chrome.runtime.connectNative`) 으로 옮기기를 제안한다.

| | 지금 (HTTP 포트) | 네이티브 메시징 |
|---|---|---|
| 포트 | 연다 (다른 프로그램과 겹침, 2 판에서 실제로 겹쳤음) | 열지 않는다 |
| 누가 말할 수 있나 | 출처 고정 · 헤더 검사로 막음 | 등록된 확장 id 만 (브라우저가 막음) |
| 설치 | 서버만 띄우면 됨 | 동반 앱 설치 때 운영체제에 등록 (Windows 는 레지스트리) |
| 동반 앱이 꺼져 있을 때 | 확장이 실패를 받음 | 확장이 부르면 브라우저가 호스트를 띄움 (포트가 열린 동안만 산다) |

**프로세스는 하나만 쓴다.** 브라우저가 띄우는 네이티브 호스트는 늘 떠 있는 동반 앱 (휴대폰 화면 · MCP) 과 다른 프로세스다. 그래서 호스트는 **얇은 중계**로만 두고, 받은 메시지를 실행 중인 동반 앱에 이름 있는 파이프 (Windows) 나 유닉스 소켓으로 넘긴다. 저장 (SQLite) 에 쓰는 것은 동반 앱 하나뿐이다. 동반 앱이 꺼져 있으면 호스트가 띄우거나 「동반 앱 꺼짐」을 돌려준다 (R-16-1, 확장은 `onDisconnect` 로 안다). 호스트에서 Chrome 으로 가는 메시지는 1 MB 상한이라 큰 결과는 쪼개 보낸다.

**연결이 바뀌어도 2 판의 약속은 그대로**: 출처 고정은 네이티브 호스트 등록의 「허락된 확장 id」 가 맡는다 (N-14). 동작은 동반 앱이 만들고 확장 하나 (기기 id) 에만 넘기며, 한 번만 넘기고, 2 분 안에 안 가져가면 `expired`, 가져갔는데 답이 없으면 `unknown` (R-13-1). 이 뜻은 2 판 `DESIGN.md` 12.5 와 같고, 시험도 같은 이름을 쓴다.

휴대폰 화면용 HTTP 포트 (127.0.0.1:28770, 사설망 공유로만 밖에) 는 그대로 둔다. 결정은 이 문서 검토 때 받는다 (10 절).

| 규칙 | 분류 규칙, 거르는 사이트, 비밀 이름 목록 | `rules.default.json` |

| 동작 실행 | 그 순간 다시 확인 → 실행 → 결과 | `core.js` (그대로 이어 씀) |
| 화면 | 사이드 패널 (홈 · 보드 · 찾기 · 카드), 팝업 (짧은 상태) | 동반 앱이 낸 웹 페이지 |

| 권한 | `tabs` · `tabGroups` · `alarms` · `storage` · `sidePanel` · `favicon` · `nativeMessaging` 은 설치 때, `history` · `bookmarks` 는 선택 권한으로 NEBULA 를 켤 때 (R-11-0) | 앞의 넷만 |

**주소 정리와 규칙은 하나의 JSON 과 하나의 시험 표로.** 지금은 Python 과 JavaScript 에 같은 규칙이 따로 있다. 다음 판은 규칙을 JSON 하나로, 「이 주소는 이렇게 되어야 한다」 시험 표를 JSON 하나로 두고, 양쪽 시험이 같은 표를 읽는다 (규칙이 갈라지면 시험이 실패).

**만드는 방식**: 확장 코드가 커지므로 TypeScript 와 묶음 도구 (esbuild) 를 쓴다. 2 판 `core.js` 는 이어 쓰는 것이 아니라 TypeScript 로 **다시 쓰고**, 2 판의 시험을 먼저 옮겨 같은 동작임을 확인한다. 시험은 지금처럼 Node 로 돌린다. 결과물은 빌드 없이 실을 수 있는 파일이고, 출처 정책 (`script-src 'self'`) 을 지킨다.

## 3. 자료 모양

모든 기록에 `schema` (판 번호) · `device` (만든 기기) · `at` (하이브리드 논리 시계, 5 절) 이 붙는다.

**페이지 id 는 처음 본 때 고정한다.** 2 판에는 id 를 만드는 길이 둘이다. 보관함 (`mai_tabs/library.py` 의 `item_id`) 은 정리한 주소의 해시 앞 16 자리, 1 판 내보내기 (`extension/export.js` 의 `urlId`) 는 정리하지 않은 원래 주소의 해시다. 다음 판은 보관함 방식을 잇되, 규칙을 고칠 때마다 id 가 바뀌어 옛 기록이 떨어져 나가지 않도록 id 는 처음 만든 뒤 바꾸지 않고, 정리 결과가 바뀌면 **별칭 표** (옛 정리 주소 → id) 에 더한다. Python 과 JavaScript 가 같은 주소에서 같은 id 를 내는지 시험 표에 넣는다. 특히 질의 부분의 글자 바꾸기 (`~` · `*` 등) 와 국제 도메인 (퓨니코드) 은 두 언어가 다르게 다룰 수 있어 (미확인) 시험으로 확인한다.

함께 일하는 계약은 이 표가 아니라 **스키마 파일** (칸의 형식 · 키 · 색인, JSON Schema) 이다. 구현을 나누기 전에 스키마부터 낸다 (11 절).

| 기록 | 주요 칸 | NEBULA 일 때만 |
|---|---|---|
| Page | id, 주소, 제목, 분류, 처음 · 마지막 본 때, 상태 (열림 · 대기 · 별 · 블랙홀) | |
| TabState | 탭 id, 창, 묶음, 페이지 id, 깨어 있음, 고정, 소리, 앞에 있음 | |
| Window · Group | id, 제목, 색, 탭 순서 | |
| Action · Result | 동작, 대상, 미리 보기, 결과 (된 것 · 남긴 것 · 실패와 이유), 되살리기 자료 | |
| Measurement | 시각, 브라우저 메모리, GPU 별 사용량, 동작 id | |
| TrashEntry | 페이지 id, 닫힌 때, 창 · 묶음, 되살리기 자료, 만료 | |
| Workspace | 이름, 창 · 묶음 · 탭 순서 | |

| Card | 페이지 id, 닫힌 때, 간격 단계, 답 기록, 상태 | 예 (나중에 읽기는 ORBIT 에서도) |
| Settings | 거르는 사이트, 자동 규칙, 카드 상한, 동기화, 모델 | |

**저장 크기**: 방문 기록은 시험 대상 프로필 하나에서 90 일 동안 약 3.7 만 건이었다 (2026-10-25 실측). 한 건 200 바이트로 잡으면 7 MB 안팎이라 `storage.local` (10 MB) 에 담기 빠듯하다. 그래서 확장 쪽은 IndexedDB, 동반 앱 쪽은 SQLite 를 쓴다 (N-23).

## 4. 카드 상태 기계 (05 의 3 절)

상태: `열림` → (마지막 탭이 닫힘) → `일정 중 (단계 1 ~ 4)` → `별` · `블랙홀` · `대기`.

| 사건 | 결과 |
|---|---|
| 마지막 탭이 닫힘 (대상 조건을 채울 때, R-21-2) | `일정 중`, 닫힌 때 = 지금, 단계 1 (2 일). `별` · `블랙홀` 페이지가 다시 닫히면 일정에 들어가지 않는다. `대기` 페이지는 다시 닫히면 처음부터 들어간다 |
| 간격이 됨 | 그날 카드로 낸다. 하루 설정 장수를 넘치면 넘친 것은 「오늘 더 보기」로만 볼 수 있고, 그날 안 보면 「답 없음」으로 친다 (다음 간격은 미루지 않는다) |
| 오른쪽 | `별` |
| 왼쪽 | 왼쪽 연속 + 1. 3 이면 `블랙홀`, 아니면 다음 단계 |
| 다음 간격까지 답 없음 | 「답 없음」 기록, 연속은 그대로, 다음 단계 |
| 4 단계 카드를 낸 뒤 7 일 동안 답 없음 | 「답 없음」. 그 뒤 `별` 도 `블랙홀` 도 아니면 `대기` |
| 일정 중 · 블랙홀 · 대기 페이지가 다시 열림 | 먼저 `열림` 으로 옮기고 일정을 멈춘다. 30 초 이상 머물면 `별` 로 바꾼다. 그 전에 닫히면 원래 상태로 돌아가고, 일정 중이었으면 처음부터 다시 잰다 |
| 분류별로 카드를 끔 | 그 분류의 `일정 중` 페이지는 카드를 내지 않고 일정만 멈춘다. 다시 켜면 이어 간다 |
| 블랙홀이 된 지 1 년 | 카드 한 장. 오른쪽이면 `별`, 왼쪽이나 답 없음이면 블랙홀에 그대로 두고 다시 묻지 않는다 |

카드 상태는 칸을 덮어써서 맞추지 않는다. 답과 열기 · 닫기 **사건**을 기기마다 기록하고, 합친 사건을 이 표로 다시 계산한다 (5 절).

이 표 전부가 단위 시험이 된다 (08).

## 5. 동기화와 암호화

- **변경 기록 방식**: 기기마다 자기 변경을 **하이브리드 논리 시계** (벽시계와 차례 번호를 섞어, 기기 시계가 어긋나도 순서가 뒤집히지 않는 시각) 와 기기 id 를 붙여 적고, 다른 기기의 기록을 받아 합친다. 같은 칸을 두 기기가 바꾸면 시계가 큰 쪽, 같으면 기기 id 순으로 정하고 앞의 것을 기록에 남긴다 (03 의 6b 절). 카드처럼 사건으로 정해지는 것은 사건을 합쳐 다시 계산한다. 동반 앱이 꺼진 사이 확장에 쌓인 것도 같은 방식으로 넘긴다
- **압축**: 동반 앱 (없으면 확장) 이 오래된 기록을 현재 상태 하나로 접는다. 접은 상태도 같은 시계를 단다
- **암호화**: 기기에서 암호화한 사본만 동기화할 곳에 둔다 (WebCrypto, AES-GCM). 자료 열쇠는 첫 기기에서 무작위로 만든다. 새 기기에는 이미 붙은 기기가 보여 주는 코드 (짧은 수명) 로 넘긴다. 잃어버림에 대비해 사용자가 정한 복구 문구로 자료 열쇠를 감싼 사본을 하나 둔다 (PBKDF2, 반복 수와 솔트는 구현 때 현재 권장값으로 정해 이 문서에 적는다). 열쇠와 복구 문구를 다 잃으면 사본은 못 연다 (각 기기의 자료는 남는다)
- **기기 빼기**: 기기를 빼면 자료 열쇠를 새로 만들어 다시 암호화한다. 뺀 기기는 그 뒤의 자료를 못 읽지만, 이미 받아 둔 옛 사본은 읽을 수 있다는 점을 화면에 적는다
- **지우기**: 사용자가 지우기를 고르면 각 기기와 동기화할 곳의 사본을 함께 지운다 (N-04)
- **열쇠를 둘 곳**: 동반 앱이 있으면 운영체제 보관소 (N-13). 확장만 쓰면 운영체제 보관소에 닿지 못하므로, 추출할 수 없는 WebCrypto 열쇠로 IndexedDB 에 두고 모델 자기 키 같은 비밀은 동반 앱 없이는 받지 않는다
- **어디에**: Drive 는 앱 전용 칸, 내 서버는 폴더 하나 (사설망으로 공유), 구독은 우리 중계 서버 (암호문만 받고 넘김)
- **기기 사이 명령**: 기기마다 서명 열쇠를 만들고, 명령에 서명한다. 명령에는 일회용 값 · 대상 기기 · 만료 시각을 넣고, 받는 쪽은 본 일회용 값을 기억해 같은 명령을 두 번 실행하지 않는다. 확장은 붙은 기기의 서명만 받는다 (R-42-1). Ed25519 (Chrome 137 부터 WebCrypto 기본 지원으로 알고 있음, 확인 필요), 안 되면 P-256

## 6. 메모리 실측 (동반 앱)

- 2 판의 `memory.py` 를 이어 쓴다: Chrome 프로세스의 전용 메모리 합 (약 0.1 초), GPU 는 `nvidia-smi` 와 Windows 의 GPU 메모리 계수기
- 재우기 · 닫기 직전과 20 초 뒤 (R-09-1). 다른 프로그램 몫이 섞인다는 표시 (R-09-3)
- 예상 절감 = 이 기기의 지난 실측에서 「재운 탭 하나당 평균」 (R-09-2). 첫 실측 전에는 숫자를 내지 않는다
- macOS · Linux 의 같은 값은 확인 필요 (운영체제별 프로세스 메모리 읽기)
- 탭 하나하나의 메모리를 프로세스와 짝짓는 것은 공개 확장 API 로는 안 된다고 알고 있다 (프로세스 API 는 개발 채널 전용, 확인 필요). 그래서 묶음 단위로만 잰다

## 7. 모델 연결부

```
classify(pages)  -> [{id, category, confidence}]
summarize(pages, body?) -> [{id, line}]
relate(pages)    -> [{a, b, kind, confidence}]
```

- 입력은 제목 · 주소. 본문은 사용자가 고른 탭만 (R-60-2)
- 출력은 정해진 JSON 모양. 모양이 틀리면 버리고 규칙으로 돌아간다
- 공급자: 규칙 (늘), PC 안 모델 (OpenAI 호환 로컬 서버), 클라우드 모델들, 사용자 자기 키. 어느 판에서 무엇을 쓰는지는 BM (비공개)
- 묶어서 부르기 · 한 달 상한 · 같은 사람 안 캐시. 사용자 사이 캐시는 없다
- 키는 운영체제 보관소 (N-13)

## 8. 에이전트 창구 (MCP)

- 동반 앱이 stdio MCP 서버로 뜬다. 포트를 열지 않는다 (R-25-3)
- 도구 셋: `search(query, limit)` · `recent(days)` · `page(id)`. 모두 읽기 전용 (R-25-1)
- 결과의 모든 글 칸은 「웹사이트가 정한 글」 표시 안에 넣고, 도구 설명에 「자료이지 지시가 아니다」를 적는다 (R-25-2)
- 켤 때 「결과가 에이전트의 모델 공급자에게 간다」를 알리고 동의를 받는다 (R-25-4)
- 거르는 사이트 · 블랙홀 · 지운 것은 결과에 나오지 않는다 (블랙홀은 사용자가 묻을 때만)

## 9. 2 판에서 옮기는 길

1. 동반 앱이 `~/.mai/tabs/library.json` 을 읽어 새 저장 (SQLite) 으로 옮긴다. 옮기기 전에 사본을 남긴다 (N-31)
2. 확장은 새 판이 처음 뜰 때 옛 `chrome.storage.local` 의 기기 id 를 이어 쓴다
3. 2 판의 화면 (127.0.0.1:28770) 은 한 판 동안 함께 두고, 사이드 패널이 같은 일을 하면 내린다
4. 2 판의 시험 (85 개: Python 40 · 36, 확장 9, 2026-10-25 다시 셈. 실제 Chrome 11 가지) 중 동작에 관한 것 (중복 · 재우기 · 닫기 · 열기 · 거부 이유 · 실제 Chrome 확인) 은 다음 판에서도 통과해야 한다. HTTP 연결 자체를 시험하는 것은 네이티브 메시징 시험으로 바꾼다
